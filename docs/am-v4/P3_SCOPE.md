# AM V4 — границы фазы 3

Пользователь вызвал «AM V4» и прямо разрешил начать следующую фазу. Это разрешение на реализацию, проверки и отдельный PR p3; правило исходного SPEC оставлять PR открытым до подтверждения слияния сохраняется.

База: main 465881b082bbc52b2f785bfd334fbb99f5619d4f; P1 и P2 уже объединены и опубликованы. Ветка feature/qualifiers-p3. Первым коммитом обновлены прежние устаревшие AM_V4.md/state.json; историческая блокировка разрешения на merge P1 больше не актуальна.

В p2 по дополнению пользователя уже вошли реальные DE8/GSL16 BO3, ручное/тренерское участие, усталость за серию, региональные призы/очки, приглашение на главной, три вкладки и трофей-инвайт. Они сохранены и проверяются повторно.

P3 завершает пропорциональное сжатие плотных календарных окон, полный регламент известных конфликтов участников и турнирной регистрации пятёрки. Неизвестные будущие поля обычных legacy-турниров рассматриваются консервативно для календаря игрока; их регламент и отбор не меняются. Поля других клубов проверяются по фактически подтверждённым обязательствам. Поздняя внешняя бронь после закрытия списка требует устранить конфликт или отказаться: пересчёта закрытого поля нет.

Новые необязательные поля: S.qualifiers.phase3, qualification.calendarVersion/calendar/initialInvited/inviteChanges3/calendarBlock3, event.registration3. QualVersion остаётся 1, gameVersion 2.6, контейнер v:1 и ключи прежние. Уже замороженная P2-квалификация и её активная карта не переводятся на новый календарь. Только pending-события и следующие объявления используют P3.

P3b (отношения/запрос wildcard), окончательная общая приёмка интерфейса P4 и 200 сезонов баланса P5 не выполняются в этом PR. Проверка четырёх событий с записанными исходами — тест календаря, а не баланс сезона. Текущий недельный остаток неизвестен; 61% — последний пользовательский замер от 21 октября.

Во время реализации облачная среда кратко стала unavailable/offline. Доступ к рабочим файлам восстановился; локальные Node и Chromium действительно выполнялись после восстановления. Временные результаты пишутся только в /tmp. Архив Ancient-Manager-v2.1/ и test-results/ не изменяются.
